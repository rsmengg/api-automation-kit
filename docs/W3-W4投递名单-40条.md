## I. 六套话术模板（T1–T6）

> 方括号内是要替换的变量。`[X]` 在清单表最后一列给出。
> **所有"人日/分钟"类的数字，前 3 单用模板里的示例口径，W7 之后必须换成你自己交付的真实数据**——编数字被当场戳穿一次，这个平台就再也拿不到单了。

### T1 · 接口自动化整包（最常用，也最值钱）

> 你好，看到贵司在找「接口自动化」这块的人。
>
> 问一个可能踩过的坑：你们接口回归现在是人工点还是脚本跑？如果是人工，一轮大概要多久？
> （我做过的一个零售 ERP，约 80 个接口人工点 1.5 人日一轮；改成 Pytest + Allure 之后一条命令 6 分钟跑完，失败自动落盘 request / 响应 / traceback，不用再开抓包工具对着找。）
>
> 我能直接给你的是一套跑起来的东西：`--base-url` 一个参数切环境（测试/预发/灰度），失败的用例自动截图式留证，Allure 报告发群里就能看，GitHub Actions / Jenkins 接上就行。
> 另外每单一份《接口风险清单》+《用例维护手册》，你们的人照着手册能自己加用例。
>
> 报价：整套约 50 个接口 ¥8,000–15,000，3–4 周；如果只是补 10–20 条核心接口，¥3,000 起、5 天内交付。
> 不合适也没关系，可以聊两句。我的开源实现在这：https://github.com/rsmengg/api-automation-kit

### T2 · 压测（JMeter / 定位瓶颈）

> 你好，看到贵司在做压测 / 性能测试。
>
> 想问一句：现在的压测是拍脑袋定 QPS，还是有基线？跑完能定位到是接口慢、SQL 慢，还是连接池/线程池打满吗？
> 大多数压测报告只给一张 TPS 曲线，说不清瓶颈在哪，最后还是得回到人力排查。
>
> 我交付的是【压测脚本 + 分层的性能报告 + 瓶颈定位结论】三件套：脚本可改参数重跑，报告按接口/按 SQL/按线程维度拆分，最后一页直接写"瓶颈在 order_query 的 N+1 查询，加复合索引可降 60%"。
> 用 JMeter / k6 都行，看你们现有栈。压测类报价 ¥2,000–8,000，看接口数和轮次。
>
> 我的测试脚手架参考实现在这：https://github.com/rsmengg/api-automation-kit

### T3 · Go 服务 / 内部小工具开发

> 你好，看到贵司在招 Go 方向的开发。
>
> 想确认一下场景：是新增业务接口，还是内部工具/中间件这一层？
> 我这边是测试开发转 Go，主要做的是【接口层 + 内部工具】这一类：短生命周期的小服务、鉴权/限流中间件、批量任务、对账脚本、开源组件的二次封装。
>
> 特点是交付即能跑：Go module 结构清晰、配置项走环境变量不打进镜像、接口带 Swagger、压测和用例一起给。
> 报价按人日 ¥800–1,200，或者整包一口价。可以先聊 20 分钟确认范围，不收费。
>
> 参考实现（Python 侧脚手架，Go 侧按同一套设计）：https://github.com/rsmengg/api-automation-kit

### T4 · 移动端（Monkey / 兼容性 / 自动化）

> 你好，看到贵司在做移动端稳定性 / 兼容性测试。
>
> 问个实际情况：Monkey 现在是自动跑还是手点？崩溃和 ANR 是人工看 logcat 还是能自动归集？
> 大多数跑出来的 Monkey 结果是一堆 raw log，最后还得人肉翻，等于没省人力。
>
> 我这块能做的是：跑批 + 崩溃/ANR 自动采集与去重 + 按机型维度出一张表（哪个系统版本哪台机挂了），失败场景自动录屏留档。
> Android 用 Monkey/Appium 都行，iOS 走 xcuitest；顺带能接 ADB 批量安装卸载。
> 报价 ¥2,000–6,000，看机型数量，一般 3–5 天出结果。
>
> 参考：https://github.com/rsmengg/api-automation-kit

### T5 · CI / 流水线 / 测试平台（单价最高，话最短）

> 你好，看到贵司在改 CI 流水线 / 搭测试平台。
>
> 想问一句：现在发版的门禁是什么？是人工确认还是流水线能拦住？
> 如果门禁还是靠人，那自动化跑完的用例其实没发挥价值——**只有把"跑失败就拦住发布"接进去，才叫门禁。**
>
> 我能做的：把现有接口用例接进你们的 CI（GitHub Actions / Jenkins / GitLab CI 都行），失败即阻断，报告自动归档，异常时拉企微/钉钉群。
> 打包成一条流水线大约 ¥4,000–10,000，一周内接入。需要我先看你现有流水线再报价。
>
> 我这套脚手架自带 GitHub Actions 配置：https://github.com/rsmengg/api-automation-kit

## IV. 回复里怎么放仓库链接（有讲究）

**放链接的时机**：不要第一条消息就甩链接。平台投标区第一条只写清楚"我能解决什么 + 数字"，等对方回一句"你做过的项目看看 / 发我资料"，**或者第二条开始**，再放。

**放法**：

```
仓库地址（可公开跑的，不是 demo 片段）：
https://github.com/rsmengg/api-automation-kit
README 里有本地 mock 服务，clone 下来一条命令就能跑通，不用你准备环境。
```

**为什么这么放**：外包客户最怕两件事——「跑不起来」和「代码是玩具」。你主动说"clone 下来一条命令能跑通"，比说十句"专业可靠"有用。

**对方不点开怎么办**：正常。放链接的作用是**让他去搜你**，不是当场说服他。被搜索一次，你就从"一个投标的"变成"有作品的"。

**链接只放一次**。对方再问就重复发，别每句都带。

## VI. 三条硬规矩（发之前默念）

1. **不投涉密单**：金融/政务/公安/军工/医疗处方/POS 收单类，一律不问。这类单子给的钱再多，一个交付就够你吃两年官司。
2. **不问生产库、不接生产权限**：客户说"顺便看一眼生产环境"——拒。这是所有翻车里最贵的一句。
3. **不在公司设备/账号/网络下发任何投递动作**。用手机流量 + 私人账号，投稿话术里的行业案例一律说"某零售 ERP / 某电商中台"。
