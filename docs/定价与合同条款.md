# 定价、收款与避坑条款

## 一、三档报价表（说法要统一，别临场乱报）

| 档位 | 内容 | 报价 | 周期 | 谁该接 |
| --- | --- | --- | --- | --- |
| 小活 | 单接口补自动化 / JMeter 压测脚本 / Monkey 跑包 | ¥2,000 起 | 2–5 天 | 用来破零、攒评价 |
| 中型 | 整套框架 + 约 50 接口 + CI 接入 + 手册 | ¥8,000–15,000 | 3–4 周 | 主力收入 |
| 长期 | 包月驻场，每周固定维护 + 每周一份回归报告 | ¥6,000–12,000/月 | 3 个月起签 | 稳定现金流，最优 |

换算锚点（被砍价时用）：中型单按 3 周、每周 40 工时算 ≈ 240 工时 × ¥40/h ≈ ¥9,600。
**报 8k 是底价不是均价**，对方砍到 6k 也能接，砍到 4k 以下就别接了。

## 二、收款节奏（写进需求文档第一页）

```
立项 → 首付 40%  →  用例跑通 / 脚本交付 → 交付款 50%  →  验收期满 N 天 → 尾款 10%
```

-  Platforms 单（程序员客栈 / 码市 / Upwork）走平台担保，别私下绕单，省 10–20% 抽成但失去保护。
-   单笔 <¥5,000 且客户是老熟人：可以首付 50% + 尾款 50%。
-   **任何"先全款再动工"都拒**；**任何"先做完看看满意再付"也拒**（你会被无限消耗）。
-   私单先签一页《需求确认书》：接口清单、环境地址、交付清单、验收标准、付款节点、超时免责。
    没有这页纸，后期加需求一定扯皮——加需求加钱，这是铁律，第一次就要说出口。

## 三、报价必须先问的三个问题

1. **接口有几条？** 少于 10 条不值得做自动化，客户自己也知道，直接劝退反而加分。
2. **有没有测试/预发环境地址？** 没有环境 = 我打桩交付，工作量砍半，报价也跟着减半。
3. **谁提供接口文档？** Swagger / Postman / 内部 wiki 都行；什么都没有，我用抓包的流量逆向，
   但要加 20% 工作量。

## 四、必须写进交付物的免责条款（保护你自己）

-   交付的脚本只覆盖**测试/预发环境**；生产环境变更需客户侧执行，我方不持有生产权限。
-   用例中的账号、令牌、密钥一律由客户提供；我交付的是"塞进配置位"的占位符，不含明文凭据。
-   涉及第三方支付、短信、风控的接口，需客户开启沙箱或提供打桩服务，否则不纳入首轮范围。
-   验收期为交付后 5 个工作日，超时未反馈视为验收通过，尾款到期结清。
-   我方代码不含公司任何业务资产；示例项目已全部脱敏。

## 五、翻车信号（出现立刻刹车）

| 信号 | 处理 |
| --- | --- |
| 需求每三天变一次 | 停下来重签《需求确认书》，已做部分按周计价 |
| 客户要求"顺便看下生产库" | 拒绝。这是你职业生涯里最贵的一句话 |
| 验收拖过两周 | 发一次"已交付待验收"函，第 21 天发第二次，第 30 天走尾款流程 |
| 对方用公司身份压价到低于 2k | 婉拒，把时间留给能成交的客户 |
