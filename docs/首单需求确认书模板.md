# 需求确认书（首单专用模板）

> 用途：**私单/闲鱼定制/朋友介绍**这类不走平台担保的活，开工前先让客户在这份上确认一次。
> 走程序员客栈/码市/Upwork 的平台单，**平台自带确认流程，不用这份**——但里面的条款仍然要读一遍，尤其是付款节点和免责那两节。
>
> 这不是合同（不用那么重），是**开工前的一页纸**。它的唯一作用：证明"我们商量好的范围是这些"。
> 出了这页纸，对方加需求 = 加钱。这话第一次就要说出口，晚了就成 ascot。

## 微信/飞书版（先发这个，求一句"确认我就开工"）

把下面整段复制过去，把方括号里的替换掉。**控制在 8 行以内**，客户才愿意看。

```text
【接口自动化 · 项目需求确认】
项目：X（脱敏用名，比如"某零售 ERP 订单服务"）
范围：接口自动化脚本 + Allure 报告 + CI 接入，共约 [N] 个接口
环境：测试 / 预发（客户侧提供地址与账号）
交付：①可运行脚本仓库 ②Allure 报告样例 ③CI 流水线配置 ④《接口风险清单》⑤《用例维护手册》
周期：[N] 个工作日
报价：¥[N]，首付 40% / 用例跑通 50% / 验收期满 10%
不含：生产环境操作、第三方支付/短信/风控接口的联调（如需另议）
验收：交付后 5 个工作日内反馈，超时未反馈视为验收通过

以上如无异议，回我"确认"两个字我就开工；中途加接口/加环境，按 ¥[X]/接口 追加，另计。
参考实现（可 clone 跑通）：https://github.com/rsmengg/api-automation-kit
```

## 正式版（客户要求书面 / 金额 >¥5,000 时用，可下载打印）

### 一、项目信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | （脱敏名，例：某零售 ERP · 订单服务接口自动化） |
| 甲方 | / 对接人 / 联系方式 |
| 乙方 | （你的名字 / 工作室名） |
| 项目周期 | 自 年 月 日起至 年 月 日止，共 N 个工作日 |
| 报价 | ¥ （含 / 不含税，是否含远程协作费） |

### 二、接口范围（**这一栏是全部争议的来源，必须逐条填**）

| # | 接口名 | 方法与路径 | 必测场景 | 优先级 |
| --- | --- | --- | --- | --- |
| 1 | | GET /xxx | 正常 / 参数缺失 / 未授权 / 超时 | P0 |
| 2 | | | | |
| … | 合计约 N 个接口 | | | |

优先级定义：**P0 = 发版必回归；P1 = 核心路径；P2 = 边缘场景**。
**约定：P0 全量覆盖，P1 覆盖主流程，P2 视时间取舍。** 白纸黑字写清楚，省得最后"我以为你都要测"。

### 三、环境信息（客户侧提供，填不下的先空着）

| 项 | 测试环境 | 预发环境 | 生产 |
| --- | --- | --- | --- |
| 环境地址 | | | 不涉及（乙方不持生产权限） |
| 账号/令牌 | 客户提供，乙方仅填占位符 | 同 | — |
| 接口文档 | Swagger / Postman / Wiki / 抓包流量 | | |
| 依赖的第三方 | （支付/短信/风控/登录）是否可打桩 | | |

**三条硬话必须写进去**：
1. 甲方提供测试/预发环境地址、账号令牌与文档；凭证仅以占位符形式写入配置，乙方不留存明文。
2. 第三方接口（支付、短信、风控、登录）需甲方开启沙箱或提供打桩，否则不纳入首轮范围。
3. 环境不通/文档缺失导致无法执行的用例，不计入交付覆盖率；需要人工逆向流量补用例的，加 20% 工作量。

### 四、交付清单（写数字，不写形容词）

| # | 交付物 | 形式 | 验收方式 |
| --- | --- | --- | --- |
| 1 | 可运行用例脚本 | 代码仓库（含 README） | clone 后一条命令跑通 |
| 2 | Allure 报告样例 | 报告文件 + 生成脚本 | 打开能看到用例树 |
| 3 | CI 流水线配置 | GitHub Actions / Jenkinsfile | 流水线跑出绿/红 |
| 4 | 《接口风险清单》 | Markdown | 列出每接口风险等级与建议 |
| 5 | 《用例维护手册》 | Markdown | 新增用例的步骤说明 |
| 6 | 交付说明会 | 线上 30 分钟 | 演示 + 答疑 |

### 五、验收标准

- 验收期：交付后 **5 个工作日**。
- 验收期内甲方提出修改意见，属于**范围内**（已确认的接口与场景）的免费修 1 轮；第 2 轮起按 ¥[X]/人日 计。
- **验收期届满未反馈书面意见，视为验收通过，尾款到期结清。**
- 覆盖率口径：P0 接口 100% 可执行（不要求 100% 通过——挂了的用例如果本身是产品 bug，走单子流程，不是你的锅也不扣你钱）。

### 六、付款节点

```
立项 → 首付款 40%  （开工前）
用例跑通 / 脚本交付 → 交付款 50%  （第 N 个工作日末）
验收期满 5 个工作日 → 尾款 10%
```

- 发票：是否需要 / 税率 / 开票主体（个体户也能开，问一句）。
- 走平台（程序员客栈/码市/Upwork）的按平台节奏，但**总比例不变**。
- **先全款再动工 → 拒；先做完看看满意再付 → 拒。**

### 七、变更条款（**加需求加钱，写在这儿**）

- 本合同范围以第二节《接口范围》为准。
- 新增接口：¥[X]/接口（含用例编写 + 报告 + 回归 1 轮），工期顺延。
- 新增环境（测试→预发→灰度）：单次 ¥[X]，工期顺延 2 天。
- 需求在开工后 3 天内变更超过 5 个接口：重新报价，已做部分按 ¥[X]/人日 结算。
- **任何变更以书面（含微信文字确认）为准，口头说"顺手加一下"不算。**

### 八、责任与免责

- 乙方交付物仅覆盖测试/预发环境；**生产环境任何变更由甲方执行，乙方不持有生产权限、不接触生产数据。**
- 乙方不得将甲方数据、接口凭证、业务信息用于本合同以外的任何用途，交付样例一律脱敏。
- 甲方提供的凭证若因泄露造成损失，乙方不承担责任（乙方已尽到"不明文存储"的义务）。
- 因甲方环境不稳定、第三方服务不可用导致的失败用例，不计入乙方交付质量。
- 乙方可在本项目对外表述中，将本项目称为"某零售 ERP / 某电商中台"类脱敏描述（**不提真实甲方名称**）。

| --- | --- | --- |

| 日期 | | |

**确认方式**：打印签字回传 / 微信文字"确认" / 邮件回复本函，三者之一即生效。

## 三个填错就废的坑

1. **第二节接口范围留空只写"约 50 个接口"** ——客户会认为全部接口都是你的活，最后你被 300 个接口套牢。**逐条列，列不完就写"首轮 P0 的 N 个，其余随二期"。**
2. **第五节的验收期不写天数** ——"验收通过"永远没人主动说，写了 5 个工作日才有"过期即通过"这把刀。
3. **第七节不写单价只写"另行协商"** ——"另行协商"在客户口语里等于"免费给你做"。

## 什么时候不用这份

- ¥2,000 以下的小活，用微信版那段话就够了，别让 99 块的单子走 9 页流程，反而显得不爽快。
- 走平台的单，平台合同优先。
- **唯一例外**：不管多少钱，只要对方是"朋友介绍的 / 私聊定的 / 不走平台"，这一页纸必须有。
